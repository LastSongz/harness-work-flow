# Spec PR 评审清单

## 基本信息

- [ ] Spec 位于 `specs/<需求编号>-<简短名称>/`。
- [ ] PR 只包含规格、设计和必要的探索结论，不混入正式业务代码。
- [ ] 原始需求和相关材料已建立链接。

## 业务评审

- [ ] 目标、非目标和业务价值明确。
- [ ] 业务术语只有一种解释。
- [ ] 正常、异常和边界规则完整且不矛盾。
- [ ] 验收标准可观察、可测试。
- [ ] 当前开发路径没有未解决的业务问题。

## 开发评审

- [ ] 影响范围和依赖已经识别。
- [ ] 接口、数据、错误和兼容策略明确。
- [ ] 安全、性能、发布和回滚风险得到处理。
- [ ] 任务可以小步实施和独立验证。

## 测试评审

- [ ] 每条业务规则至少由一个验收场景覆盖。
- [ ] 异常、权限和边界场景具备预期结果。
- [ ] 回归范围和测试数据要求明确。
- [ ] 无法自动化的项目说明了人工验证方式。

## 合入条件

- [ ] 业务、开发和测试负责人均已批准。
- [ ] Spec 状态已经更新为 `Approved`。
- [ ] 必须问题已经关闭，非阻塞问题有负责人和期限。
