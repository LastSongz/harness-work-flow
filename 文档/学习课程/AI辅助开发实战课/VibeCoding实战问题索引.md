## 如何使用这个索引

1. 先找到最接近当前处境的问题描述。
2. 打开对应文章的“实战速查卡”，先执行“先做什么”。
3. 需要理解原因时，再回到正文。
4. 完成后检查“完成证据”，不要只依据 AI 的自我评价。

当前索引优先收录已经完成工具书化整理的主题文章。后续每完善一篇，就把它能解决的问题、工作阶段和产物入口补充到这里。

## 按实际问题查

### AI 一收到需求就开始改代码

- 还没看现有实现，就创建了多个文件。
- 根据文件名猜测调用链和业务规则。
- 你还没确认方案，它已经声称功能完成。

先查：[[01-从VibeCoding到Agentic Engineering#实战速查卡]]

立即采用：暂停修改，要求先输出代码地图、已确认事实、未知问题、影响文件和高风险点，随后停止等待确认。

### 功能能运行，但不知道能不能交付

- 只调用了一次成功请求。
- AI 表示测试已经通过，但没有展示测试范围。
- 退款、重复请求、并发和审计仍然不清楚。

先查：[[01-从VibeCoding到Agentic Engineering#“能跑”和“可交付”的差别]]

立即采用：把“正常路径成功”改写为风险清单，并为每一类风险指定验证证据。

### AI 正在替我决定业务规则

- AI 自己决定哪些订单状态允许取消。
- AI 在没有确认的情况下选择事务或补偿方案。
- “合理处理”“完整实现”被模型自行解释。

先查：[[01-从VibeCoding到Agentic Engineering#三方分别负责什么]]

立即采用：把任务拆成“人决定、Agent 执行、工具证明”，业务取舍和风险接受必须回到人。

### 任务越做越大，不知道何时暂停

- 每次修正都会引出更多文件修改。
- 探索、设计、实现和提交混在同一轮中。
- Agent 没有明确的等待点。

先查：[[01-从VibeCoding到Agentic Engineering#最后写下本阶段的停止条件]]

立即采用：写清当前允许做什么、禁止做什么、必须交付什么，以及产出后等待谁确认。

### Agent 表现不稳定，不知道该怪模型还是环境

常见表现：同一个模型在不同仓库差异很大；命令跑不起来；Agent 反复违反约定。

先查：[[02-Agent Harness原理#实战速查卡]]

立即采用：分别检查模型、指令、工具、上下文、权限和反馈，不要先入为主地只换模型。

### 不知道该选 IDE、CLI 还是云端 Agent

常见表现：所有任务都用同一种工具；敏感数据边界不清；强模型承担大量机械工作。

先查：[[03-工具和模型选择#实战速查卡]]

立即采用：按探索、决策、实现、验证和交付拆分任务，再根据反馈距离、数据边界和副作用路由工具。

### Agent 总是误解需求或扩大范围

常见表现：一句模糊需求生成大量代码；“完整、优雅”被随意解释；不知道何时停止。

先查：[[04-高质量任务简报#实战速查卡]]

立即采用：补齐目标、背景、范围、约束、验收、验证和停止条件，让 Agent 先复述再动手。

### 接手陌生仓库，不知道从哪里读

常见表现：搜索到很多同名方法，却没有真实调用链；事实与推断混在一起；影响面不清。

先查：[[05-AI阅读陌生代码库#实战速查卡]]

立即采用：从业务入口追踪到领域规则、持久化、外部依赖和错误出口，每条结论附路径与符号证据。

### Spec 太短或太细，无法稳定指导实现

先查：[[06-最小可执行Spec#实战速查卡]]。立即采用：用业务规则、可观察场景、非功能要求和不包含范围描述行为，把类和表结构留给 Plan。

### Agent 总是直接采用第一个实现方案

先查：[[07-Plan Before Code#实战速查卡]]。立即采用：比较至少两个可行方案，记录选择与放弃理由，再展开文件、符号、测试和停止条件。

### 任务太大，Diff 无法审查或回滚

先查：[[08-任务拆分#实战速查卡]]。立即采用：按可观察行为切成垂直切片，为每片声明文件所有权、完成证据和回滚方式。

### 会话越来越长，Agent 开始遗忘约束

先查：[[09-上下文工程#实战速查卡]]。立即采用：围绕下一个决策筛选上下文，删除噪声，并生成包含证据和禁止项的交接摘要。

### 同一条规则每次都要重新提醒 Agent

先查：[[10-项目长期记忆#实战速查卡]]。立即采用：把重复纠正分类为自动检查、长期规则或一次性上下文，只沉淀短小且可验证的长期规则。
