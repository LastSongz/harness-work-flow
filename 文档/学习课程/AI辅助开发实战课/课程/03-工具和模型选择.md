# 03 工具和模型选择：IDE、CLI、云端 Agent 与任务路由

## 本课目标

- 不按品牌站队，而是按任务、环境和风险选择执行方式。

## 讲解：先选工作形态，再选具体产品

工具选择至少考虑五个维度：

1. **反馈距离**：能否直接运行项目命令、读取错误和继续修正。
2. **上下文范围**：单文件补全、跨仓探索还是长时间后台任务。
3. **数据边界**：代码和日志能否离开本机，是否包含客户或生产数据。
4. **副作用**：是否会改文件、创建 PR、访问外部服务或执行部署。
5. **交互需要**：任务是否需要你频繁确认业务决策。

IDE 内联补全适合局部、低歧义编辑；本地 CLI/桌面 Agent 适合搜索、命令执行和迭代调试；云端 Agent 适合环境可复现、范围清楚、能通过 CI 验证的后台任务。任何形态都不自动等于“更安全”或“更聪明”。

模型也应路由：高推理模型用于陌生架构、复杂调试和方案权衡；快速模型用于格式化、重复测试补齐和文档机械更新；视觉模型只在截图、设计稿或运行界面确实是关键证据时使用。

## 示例：订单取消任务路由

| 子任务 | 推荐形态 | 模型倾向 | 理由 |
|---|---|---|---|
| 阅读状态流转与退款调用链 | 本地 Agent/CLI | 强推理 | 需要跨文件搜索与追踪 |
| 补一个明确的 DTO 字段 | IDE | 快速 | 范围小、即时审阅 |
| 比较同步退款和异步补偿 | Ask/Plan 模式 | 强推理，多方案 | 需要权衡一致性与复杂度 |
| 批量生成边界测试草案 | 本地或云端 Agent | 快速/均衡 | 可由测试反馈筛选 |
| 处理含生产订单号的日志 | 本地受控环境 | 强推理 | 数据不能外发 |
| 创建 PR | 具备 GitHub 权限的 Agent | 均衡 | 必须先通过 Diff 和 CI 门禁 |

## 操作步骤

1. 把功能拆成探索、决策、实现、验证、交付五类任务。
2. 为每类任务标记数据敏感度、所需工具和最大副作用。
3. 选择满足要求的最小能力组合，不为一个 DTO 修改启动复杂多 Agent。
4. 写降级方案：云端环境无法启动依赖时，回到本地执行；强模型不可用时，缩小任务而不是降低验证标准。
5. 记录切换理由，便于复盘成本、速度和缺陷率。

## 练习

为以下三项选择工作形态并写一句理由：

- 追踪 `cancel()` 为什么在并发请求下重复调用退款。
- 根据已确认的 8 个用例生成 JUnit 参数化测试骨架。
- 使用真实生产日志判断退款失败原因。

建议答案：第一项用本地强推理 Agent 并运行并发测试；第二项可用快速模型生成后人工审阅；第三项只在获批、脱敏、受控环境中处理，不能直接粘贴到外部聊天。

## 验收标准

- [ ] 路由矩阵覆盖探索、实现、验证和交付。
- [ ] 每个选择都能解释反馈、数据和副作用。
- [ ] 至少写出一个工具不可用时的降级方案。
- [ ] 没有把“最强模型”当作所有任务的默认答案。

## 课后小结

高质量工作流允许更换工具，却不降低 Spec、测试、审查和权限标准。下一课将把需求整理成任何 Agent 都能理解的高质量任务简报。
