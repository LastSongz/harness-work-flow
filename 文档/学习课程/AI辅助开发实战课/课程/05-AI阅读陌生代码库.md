# AI 阅读陌生代码库：代码地图、入口、调用链、影响面

导航：上一篇 [[04-高质量任务简报]] · [[VibeCoding课程首页]] · [[VibeCoding课程总纲]] · 下一篇 [[06-最小可执行Spec]]

> [!summary] 核心问题
> 搜到一组文件名并不等于理解系统。真正的代码库探索要回答：请求从哪里进入、规则在哪里生效、数据写到哪里、外部副作用如何发生，以及哪些结论仍然只是推测。


## 从“仓库里有什么”到“行为如何发生”

阅读陌生仓库应从业务问题出发，逐层缩小范围：

1. **边界层**：应用入口、模块、构建方式、运行和测试命令。
2. **业务层**：Controller、用例服务、领域对象和状态规则。
3. **依赖层**：数据库、消息、支付、鉴权、审计和异常映射。
4. **证据层**：现有测试、相邻实现、配置和历史决策。

符号索引、LSP、AST/知识图谱适合查定义、调用者和影响面；文本搜索适合错误消息、配置键和业务字面量。不要把全文搜索到的同名方法直接当作真实调用链。

## 让 Agent 输出可审查的代码地图

```text
只读探索订单取消相关代码，不修改文件。

请回答：
1. 应用如何构建、运行、测试？
2. 订单查询和状态变更的 HTTP 入口在哪里？
3. 从 Controller 到数据库的调用链是什么？
4. 哪些代码调用 RefundGateway，幂等键如何传递？
5. 状态校验、异常映射、事务、并发控制和审计分别在哪里？
6. 找到 2 个最接近的现有测试作为实现模式。

每个结论附文件路径和符号；把“已确认事实”和“根据命名推断”分开。
最后列出可能受影响文件和仍需业务确认的问题。
```

期望输出不是一串文件名，而是结构化关系：

```text
POST /orders/{id}/cancel
→ OrderController.cancel
→ OrderApplicationService.cancel
→ Order.cancel（领域规则）
→ OrderRepository.save
→ RefundGateway.requestRefund（仅 PAID）
→ OrderExceptionHandler（错误到 HTTP）
```

如果仓库实际没有 `cancel` 方法，Agent 应指出缺口，并从相邻的“订单关闭”或“售后退款”流程提取模式，不能虚构调用链。

## 可以怎样做

1. 读取根目录说明、构建文件和项目规则，确认仓库边界与命令。
2. 搜索订单 API 入口和 `OrderStatus` 定义。
3. 用“定义→调用者→被调用者”追踪一次真实状态变更。
4. 查找事务注解、锁/版本字段、异常处理和审计实现。
5. 查找退款接口的生产实现、测试替身和幂等参数。
6. 读取两个相邻测试，记录命名、夹具、断言和运行命令。
7. 输出影响面：必须改、可能改、明确不改。

## 动手梳理

根据下面的假设仓库，写一张代码地图：

```text
controller/OrderController.java
application/OrderApplicationService.java
domain/Order.java
domain/OrderStatus.java
infrastructure/JpaOrderRepository.java
integration/PaymentClient.java
support/ApiExceptionHandler.java
```

至少写出一个 HTTP 入口、一个领域规则位置、一个外部依赖、一个错误出口和两个测试候选。再写两条不能仅凭目录确认的事实，例如事务边界和并发策略。

## 自查清单

- [ ] 每条关键结论都有文件或符号证据。
- [ ] 代码地图覆盖入口、业务、持久化、外部依赖和错误出口。
- [ ] 已确认事实与推断分开记录。
- [ ] 影响面包含必须改、可能改和明确不改。
- [ ] 尚未授权 Agent 写代码。

## 实战速查卡

### 什么时候查这篇文章

- 接手陌生仓库，不知道从哪里开始读。
- Agent 给出很多文件名，却说不清真实调用链。
- 根据方法名猜实现，后来发现方向错误。
- 修改一个功能前，不清楚影响哪些层和外部系统。

### 先做什么

1. 确认仓库边界、构建方式和项目规则。
2. 从业务入口追踪一次真实行为，不按目录漫游。
3. 对关键结论记录文件路径和符号证据。
4. 把事实、推断和未知问题分开。
5. 输出必须改、可能改和明确不改的影响面。

### 可直接借鉴的方法

```text
只读探索，不修改文件。
从业务入口追踪到领域规则、持久化、外部依赖和错误出口。
每个结论附文件路径与符号。
分开列出：已确认事实、根据命名推断、仍未知问题。
最后给出必须改、可能改、明确不改的文件清单，然后停止。
```

### 常见误区

- 把全文搜索结果直接当作真实调用关系。
- 只读 Controller 和 Service，不查事务、异常与审计。
- 找到一个相似实现就默认业务规则相同。
- 探索尚未完成就开始生成代码。

### 完成证据

- 入口到副作用的调用链。
- 带路径和符号的代码地图。
- 事实、推断和未知问题清单。
- 分级影响面与相邻测试样例。
