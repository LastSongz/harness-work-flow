# 高质量任务简报：目标、背景、范围、约束、验收、验证、停止条件

导航：上一篇 [[03-工具和模型选择]] · [[VibeCoding课程首页]] · [[VibeCoding课程总纲]] · 下一篇 [[05-AI阅读陌生代码库]]

> [!summary] 核心问题
> “给订单加个取消功能，注意并发，测试写全。”人类能感觉到大概意思，Agent 却必须猜测允许状态、退款规则、修改范围和完成标准。任务简报的作用，就是把这些隐含判断变成可执行合同。


## 把任务写成一张可执行工单

高质量任务简报通常包含七段：

1. **目标**：完成后用户或系统获得什么行为。
2. **背景**：为什么做、相关业务和已知事实。
3. **范围**：本次包含与不包含什么。
4. **约束**：架构、兼容、数据、安全、权限和禁止项。
5. **验收**：从外部可观察的完成条件。
6. **验证**：要运行哪些命令、检查哪些证据。
7. **停止条件**：遇到什么必须暂停并请求决定。

“使用事件驱动架构”通常是方案，不是目标；“测试一下”不是验证，因为没有命令和期望；“不要改太多”不是范围，因为无法判断哪些文件允许变化。

## 订单取消任务简报 v1

```markdown
目标：
为订单服务增加取消接口。CREATED、PAID 订单可取消；其他状态返回明确业务错误。

背景：
现有订单状态由 OrderApplicationService 维护，PAID 订单通过 RefundGateway 退款。
先探索现有代码确认这些假设，不要直接按名称猜实现。

范围：
- 包含：取消用例、幂等、并发保护、审计、单元与必要集成测试。
- 不包含：前端页面、支付供应商 SDK 升级、生产数据迁移、自动部署。

约束：
- 遵循现有 Controller/Service/Repository 分层和异常格式。
- 不修改用户已有未提交内容；不提交、不推送。
- requestId 防止重复退款；日志不得记录支付凭证。

验收：
- CREATED 取消后变为 CANCELED。
- PAID 取消只产生一次退款请求并变为 CANCELED。
- SHIPPED 返回不可取消错误；重复 requestId 返回相同结果。
- 并发取消不会重复退款，审计字段完整。

验证：
- 运行目标单元测试、相关集成测试和项目标准静态检查。
- 查看 git diff、git diff --check，并列出未验证风险。

停止条件：
- 现有状态规则与简报冲突；
- 需要数据库迁移、真实退款凭证或扩大到其他服务；
- 测试环境连续失败且无法区分代码问题与环境问题。
```

## 可以怎样做

1. 先写目标与验收，不急着指定类名和实现方案。
2. 把你认为的事实标成“已确认”或“待探索”，防止 Agent 把假设当真。
3. 用“包含/不包含”定义边界。
4. 把抽象质量要求改成可检查行为，例如把“保证幂等”改成“相同 `requestId` 不产生第二次退款”。
5. 为高风险分支写停止条件。
6. 让 Agent 先复述简报、列未知问题和预期修改文件，再授权写代码。

## 动手梳理

把“给订单加取消，注意并发，测试要全”改写成至少包含以下内容的简报：

- 两个允许状态和两个拒绝状态。
- 重复请求的可观察结果。
- 一个明确的不包含范围。
- 三条验证证据。
- 两条停止条件。

完成后删掉无法验收的形容词，如“优雅”“完善”“尽量少改”，改为具体规则。

## 自查清单

- [ ] 七段结构齐全，目标没有偷渡实现结论。
- [ ] 范围同时写了包含与不包含。
- [ ] 每条关键业务规则都有可观察验收结果。
- [ ] 验证包含具体测试、Diff 和质量检查。
- [ ] 停止条件覆盖规则冲突与高副作用扩张。

## 实战速查卡

### 什么时候查这篇文章

- Agent 经常误解需求或擅自扩大修改范围。
- 提示词很长，但完成标准仍然说不清。
- 任务中混杂事实、假设和实现偏好。
- 不知道什么时候应该让 Agent 停下来询问。

### 先做什么

1. 先写目标和外部可观察的验收结果。
2. 把事实标成“已确认”或“待探索”。
3. 同时写清包含范围与不包含范围。
4. 为高风险分支设置停止条件。
5. 让 Agent 先复述并列出未知问题，再授权修改。

### 可直接借鉴的方法

```text
目标：最终需要出现什么行为？
背景：为什么做，哪些事实已经确认？
范围：包含什么，不包含什么？
约束：必须遵守和明确禁止什么？
验收：从外部怎样观察到完成？
验证：运行哪些命令，查看哪些证据？
停止条件：遇到什么必须暂停并请求决定？
```

### 常见误区

- 用“优雅、完善、尽量少改”代替可检查规则。
- 在目标中偷渡未经比较的实现方案。
- 只写要做什么，不写明确不做什么。
- 写“测试一下”，却没有命令和期望结果。

### 完成证据

- 七段式任务简报。
- 包含与不包含范围。
- 关键规则对应的验收结果。
- 验证命令、预期证据和停止条件。

## 结语

任务简报不是提示词装饰，而是人和 Agent 之间的执行合同。它把目标、边界、证据和等待点提前说清，让后续探索与实现不再依赖猜测。延伸阅读：[[05-AI阅读陌生代码库]]。
