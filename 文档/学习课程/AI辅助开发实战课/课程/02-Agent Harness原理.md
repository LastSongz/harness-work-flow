# Agent Harness 原理：模型、指令、工具、上下文、权限、反馈

导航：上一篇 [[01-从VibeCoding到Agentic Engineering]] · [[VibeCoding课程首页]] · [[VibeCoding课程总纲]] · 下一篇 [[03-工具和模型选择]]

> [!summary] 核心问题
> 为什么同一个模型、相似的提示，在两个仓库里的表现可能天差地别？很多时候，差别不在模型，而在它周围的指令、工具、上下文、权限和反馈是否可靠。


## Agent 为什么能“动手”

普通聊天主要产生文本；编码 Agent 还可以搜索仓库、读取文件、编辑内容、运行命令并根据结果继续行动。把这些能力组织起来的运行环境就是 Harness。

一个实用的六要素模型：

| 要素 | 关键问题 | 订单取消示例 |
|---|---|---|
| 模型 | 推理能力和成本是否匹配任务？ | 架构方案用强推理模型，机械改名用快速模型 |
| 指令 | 什么必须做、禁止做？ | 先读后写，不修改支付 SDK，不自动提交 |
| 工具 | 能看到和执行什么？ | 符号搜索、文件编辑、Maven、Git Diff |
| 上下文 | 当前决策需要哪些事实？ | 状态机、退款接口、测试模式、业务 Spec |
| 权限 | 哪些动作可自动，哪些需批准？ | 读文件自动；迁移、联网、推送需批准 |
| 反馈 | 如何判断动作有效？ | 测试、编译、日志、Diff、独立评审 |

同一模型在不同 Harness 中表现可能差异很大。测试跑不起来时，继续改提示词通常不如修复依赖、启动脚本或权限配置；Agent 反复违反约定时，应检查持久规则是否清晰，而不是只责怪模型。

## 最小 Harness 清单

```markdown
目标仓库：order-service
启动位置：仓库根目录
持久指令：遵循现有分层；先运行目标测试；不得提交或推送
允许工具：代码搜索、文件读写、./mvnw test、git diff
默认权限：读取与目标文件编辑自动；联网、删除、迁移需确认
输入上下文：订单状态规则、RefundGateway 接口、相邻测试示例
完成反馈：目标测试通过 + 全量相关测试通过 + diff --check + 人工评审
```

这个清单不绑定工具。Codex 可读取 `AGENTS.md`，Claude Code 可读取 `CLAUDE.md`，Cursor 可使用 Rules；核心是六个问题都有答案。

## 可以怎样做

1. 先写任务所需的最少工具，不要默认开放所有外部系统。
2. 为每种工具标记读、写、执行和外部副作用。
3. 只装入与当前决策相关的上下文，长文档用链接或摘要。
4. 列出至少一个快速反馈和一个最终反馈：
   - 快速：单个状态机单元测试。
   - 最终：相关测试集、Diff 和人工审查。
5. 设置失败处理：命令连续失败两次时停止修改，先报告原始错误和环境假设。

## 动手梳理

假设 Agent 能读取代码，却无法访问公司制品库，`./mvnw test` 因依赖下载失败。用六要素判断问题：

- 这不是立即换模型的理由。
- 先检查工具环境、网络权限、依赖缓存和允许的替代验证。
- 如果无法安全解决，记录未验证项并停止交付结论。

再为订单取消写一份六行 Harness 清单，每个要素一行。

## 自查清单

- [ ] 六个要素都有具体配置，不只有工具名称。
- [ ] 至少一项高副作用动作需要人工批准。
- [ ] 反馈包含可运行命令或明确人工检查对象。
- [ ] 失败停止条件能防止 Agent 在错误环境中盲目重试。

## 实战速查卡

### 什么时候查这篇文章

- Agent 能读代码，却不会运行正确的测试命令。
- Agent 反复违反约定，换提示词仍然无效。
- 任务总因权限、依赖或环境问题中断。
- 不确定应该给 Agent 开放哪些能力。

### 先做什么

1. 分别检查模型、指令、工具、上下文、权限和反馈。
2. 先修复缺失的运行条件，再考虑更换模型。
3. 高副作用动作默认需要人工确认。
4. 为连续失败设置停止条件。

### 可直接借鉴的方法

```text
模型：当前任务需要怎样的推理能力？
指令：必须做什么，明确禁止什么？
工具：需要搜索、编辑和运行哪些命令？
上下文：当前决策依赖哪些事实？
权限：哪些动作自动执行，哪些必须确认？
反馈：用什么证据判断成功或失败？
```

### 常见误区

- 把环境或权限问题误判为模型能力不足。
- 默认开放全部工具，却没有副作用边界。
- 塞入大量无关上下文，反而稀释关键规则。
- 只让 Agent 自我总结，不查看真实工具输出。

### 完成证据

- 六要素清单。
- 至少一个快速反馈和一个最终反馈。
- 高副作用动作的审批边界。
- 明确的失败停止条件。

Harness 决定模型如何接触真实世界。模型能力只有通过清晰指令、可用工具、相关上下文、受控权限和真实反馈，才会变成稳定产出。延伸阅读：[[03-工具和模型选择]]。
