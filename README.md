# Harness / SDD 工作流探索

本仓库用于为华为海思供应链项目组探索一套可落地的 Harness / Spec-Driven Development（SDD）工作流。

当前阶段方案为 `v0.2`，优先阅读：

- [华为海思供应链 AI-SDD 阶段性方案 v0.2](文档/汇报材料/华为海思供应链AI-SDD阶段性方案-v0.2.md)

本阶段聚焦以下前提：

- 一个 IR 可以拆成多个候选 US，一个 US 只影响一个代码仓库；
- 正式创建 US 前，先针对候选 US 生成并评审 OpenSpec Change；
- Approved Spec 是未来系统行为的开发基线，US 只承担管理视图；
- 华为 CodeAgent 根据 Approved Spec、当前代码和项目约束小步生成代码；
- 计划、自动检查、人工评审和 Code MR 共同保障交付质量。

## 推荐的业务仓库结构

```text
<业务代码仓库>/
├── specs/
│   └── <需求编号>-<简短名称>/
│       ├── requirements.md
│       ├── design.md
│       ├── tasks.md
│       └── decisions.md
├── src/
└── tests/
```

`requirements.md` 是业务行为的权威描述；`design.md` 和 `tasks.md` 是可随实现演进的派生资产；`decisions.md` 用于收敛开发期间产生的澄清，避免事实散落在聊天和看板中。

## 最小试点方式

1. 选择一个边界清晰、预计 3～10 个开发日的小需求。
2. 将本仓库的 `模板/规格文档/` 复制到业务仓库的 `specs/<需求编号>-<简短名称>/`，并按团队约定命名。
3. 完成最小 Spec，并用 Spec PR 组织业务、开发、测试评审。
4. Spec 合入后再开始实现；Code PR 必须引用对应 Spec 路径和基线提交。
5. 交付后复盘 Spec 变更次数、返工次数、遗漏问题和交付周期。

## 当前不包含

- CodeArts、GitLab 或 Gerrit 的专属插件；
- 自动生成代码的固定 AI 工具；
- 多仓库需求编排；
- 紧急线上问题的特殊审批流程；
- 用 Spec 全量生成或覆盖存量代码。
