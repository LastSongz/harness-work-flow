# Harness / SDD 工作流探索

本仓库用于为华为海思供应链项目组探索一套可落地的 Harness / Spec-Driven Development（SDD）工作流。

当前阶段方案为 `v0.3`，优先阅读：

- [华为海思供应链 AI-SDD 阶段性方案 v0.3](文档/汇报材料/华为海思供应链AI-SDD阶段性方案-v0.3.md)

本阶段聚焦以下前提：

- 一个 US 可以包含前端、后端和测试等多个 Task，并影响多个独立实施仓库；
- 前后端独立构建和发布，但需要在同一个业务版本窗口完成交付；
- 建议一个 US 使用一个业务级 Approved Spec，各实施仓库维护独立计划；
- CodeAgent 按 Task 绑定 Spec SHA 和项目规范 SHA，小步生成代码和测试；
- 计划、自动检查、独立验收、人工评审、UAT 和生产验证共同保障质量。

## 推荐的多仓关系（待评审方案）

```text
一个 US
├── 共享 Spec 仓库：一个业务级 OpenSpec Change
├── 前端仓库：前端实施计划、Task、代码和验证
├── 后端仓库：后端实施计划、Task、代码和验证
└── 测试资产：AC 映射、跨端验证和 UAT 证据
```

共享 Spec 仓库是方案建议，不是当前既定制度。各实施仓库应固定引用同一 Approved Spec SHA，并同时记录自己的项目规范 SHA。前后端是否合仓仍待评审，但不建议仅为了 SDD 而合仓。

## 最小试点方式

1. 选择一个真实、中等复杂度、同时涉及前端和后端的 US。
2. 建立一个业务级 OpenSpec Change，并明确各实施仓库、接口人和版本窗口。
3. 业务评审场景和预期结果，开发与测试在组内评审技术计划和测试映射。
4. 各仓库按 Task 引用 Spec SHA 与 Standards SHA，实现失败时允许人工接管。
5. 完成跨端测试、UAT、上线清单和生产验证后，限时 Archive 并复盘。

## 当前不包含

- CodeArts、GitLab 或 Gerrit 的专属插件；
- 已完成验证的 CodeAgent / OpenSpec 自动化集成；
- 已批准的共享 Spec 仓库治理制度；
- 已批准的紧急 code-first 通道；
- 用 Spec 全量生成或覆盖存量代码。
